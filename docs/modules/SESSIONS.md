# Sessions
Purpose: snapshot and constrain a trading session. Table: `trading_sessions`; API `/api/v1/sessions`, `/api/v1/sessions/{id}/close`, `/api/v1/sessions/{id}/summary` and `/api/v1/sessions/{id}/trades`. Rules: OPEN/CLOSED/STOPPED, max loss/operations/payout checked before a trade, one OPEN session per account, close is idempotent and audited. Summary exposes W/L/D, P&L, win rate and streaks.

REQ-002: account rows serialize session starts and session rows serialize trades/closure on PostgreSQL. Configured risk settings are read again at start and frozen on the session; later profile changes do not change that snapshot. The risk profile remains user-scoped (Foundation model), applied to each selected account's balance.

`GET /accounts/{id}/risk-preview` returns current balance, currency, suggested stake, risk %, maximum loss/operations, minimum payout and optional target. Summary returns loss consumed based on net P&L, remaining risk, remaining operations and an explicit limit reason. Recommended stake respects per-trade, remaining-session and account-balance caps via the shared Risk Engine. Closed summaries preserve ending balance including zero; their recommendation uses ending balance rather than later account activity.

`POST /sessions` uses `SessionStartRequest`: only `trading_account_id` and optional `notes`. Additional fields are rejected with 422. Missing RiskProfile returns 409 `No risk profile configured` for both preview and creation. Snapshot fields remain stored on TradingSession and backend-derived. DRAW/CANCELLED count toward max_operations. `gross_loss` retains its existing signed (negative or zero) convention for compatibility; `loss_consumed` is a nonnegative net-loss magnitude. No schema migration for these financial review corrections.

Session history includes W/L, trade count, win rate and net P&L via a single grouped query. Frontend account/status/date filters operate on the fetched user-scoped list. Detail includes trade timestamps, summary, guardrails and associated journal notes; closure requires confirmation and disables trade entry after reload.
