# Validation
REQ-006 implements cq-validation-v1, historical validation of one immutable private strategy version. [VALIDATION_PROTOCOL](../VALIDATION_PROTOCOL.md) freezes exact boundaries, statistical gates and limitations. REQ-007 live/paper evidence is separately stored, never historical BacktestTrade evidence or an amendment of validation PASS. Scanner rechecks exact-dataset/global state each cycle; DEGRADED suspends normal items. Current provider payout is displayed separately from the compatible PASS assumption.

An owned TESTING StrategyVersion can create a fixed60/20/20 plan. TRAIN/VALIDATION/four folds use the same cq-binary-backtest-v1 event loop and origin-anchored feature rows, computed once before the sealed boundary. TEST is not simulated or persisted until explicit reveal. No strategy optimization, thresholds search or rankings. No changes to frozen feature/DSL/outcome mathematics.

APIs: GET `/validation/definitions`; POST `/validations/preview` returns a frozen-snapshot preview without computation/writes; POST/GET `/validations`; GET `/validations/{id}` and `/segments`; POST `/validations/{id}/reveal-test`. The frontend submits the preview's explicit as-of ceiling. All endpoints require authentication and private ownership, including ADMIN; requests64KiB, lists20/default100/max. Child backtests remain accessible through owned segment links, not the default manual backtest list.

Migration005 creates validation_runs/validation_segments and adds BacktestRun.purpose (existing rows MANUAL). Seven unique segments per plan, fold0 sentinel for TRAIN/VALIDATION/TEST avoids nullable uniqueness holes; folds1–4 only for WALK_FORWARD. JSONB and FK/range/version/status/verdict constraints. Phase results are transactional; immutable ORM guards prevent edits/deletes of completed evidence and frozen plans. Direct database operators are a trusted administrative boundary, not an untrusted application API.

Lifecycle: RUNNING_DEVELOPMENT→SEALED→RUNNING_TEST→COMPLETED, or active phase→FAILED. Reveal locks the version and uses a conditional SEALED claim, committed with audit and timestamp before calculation. A failed reveal cannot reseal. Audits: VALIDATION_STARTED, VALIDATION_DEVELOPMENT_COMPLETED, VALIDATION_TEST_REVEALED, VALIDATION_COMPLETED, VALIDATION_FAILED (no raw trade payloads).

Bootstrap:2000 deterministic UTC signal-day block resamples with SHA256-derived seed; mean exact unit P&L includes draws. Sufficiency precedence yields INCONCLUSIVE before performance gates. Derived per-version NOT_VALIDATED/HISTORICALLY_VALIDATED/DEGRADED does not mutate Strategy.status. HISTORICALLY_VALIDATED means only that cq-validation-v1 passed historically, not safety or future profitability. Exact replay and reused holdout warnings cannot certify external blindness or independent new evidence.

UI `/validation` lists attempts chronologically, not ranked; StrategyVersion Validate is available only under TESTING. Preview→development/folds→computational seal→explicit confirmation→test/bootstrap/gates/monthly evidence/child inspector.
